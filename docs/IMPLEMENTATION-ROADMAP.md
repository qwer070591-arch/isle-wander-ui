# Implementation Roadmap

## Phase 0 — 本次交付

八份文件：品牌、設計系統、網站地圖、使用流程、首頁規格、資料模型、媒體規劃、實作路線圖。**沒有建立 Vue 專案、安裝依賴、加入圖片、開發功能或部署。**Phase 0 驗收後再開始 Phase 1。

## Phase 1 建議順序

| 階段 | 工作 | 可驗收產物 |
|---|---|---|
| 1. 基礎 | 建立 Vue 3 + Vite + TypeScript 專案；Vue Router、Pinia；CSS tokens；路由與 404；字型載入策略 | 空頁面可導覽，1440／390px 基礎版面可用；不新增不必要依賴 |
| 2. 內容與媒體 | 建立四份 JSON、小型受控 tag 詞彙、型別與載入驗證；選定合法圖片並建授權清冊 | ID／slug／關聯有效；每張正式圖片可追溯權利與來源 |
| 3. UI 基礎 | Header、手機 Drawer、Footer、搜尋、卡片、空／錯誤狀態；鍵盤與焦點流程 | 共用元件可在 390／1440px 使用，沒有水平溢出 |
| 4. 首頁與清單 | 七段首頁、目的地／景點／住宿／故事清單與基本篩選；詳情路由 | 從首頁可抵達主要內容，URL query 可刷新與返回 |
| 5. 個人功能 | 收藏與行程編輯；Pinia + localStorage 錯誤處理、schema version | 刷新後保留資料，禁用儲存時有可見錯誤 |
| 6. 品質 | 響應式、圖片效能、對比、鍵盤、reduced motion、構建與瀏覽器檢查 | 完成驗收清單與已知限制，才能考慮發佈 |

## Phase 1 的最小功能切片

若需要分批製作，先做「首頁 → 景點搜尋／篩選 → 詳情 → 收藏」，再擴充住宿、故事與行程。這能先驗證核心探索路徑；但在宣稱 Phase 1 完成前，七個主導航的頁面都必須有可用內容或明確狀態，不能留空白連結。城市詳情與故事正文若內容素材不足，可延後到後續切片，但導航與資料關聯需一致。

## 技術界線與選擇

- 原生 CSS 與 Design Tokens 足以處理此階段的版面與微動態；GSAP 只在具體複雜時序動畫需要時評估，不預設安裝。
- icon 先使用專案自有 SVG 或現有靜態圖標；若 Phase 1 確實出現 Menu／Close 等動畫狀態且能改善理解，再評估 Morphicons 的 Vue／TypeScript 相容性、授權、維護與體積。
- 本機 JSON 的內容更新要靠重新建置／部署；沒有 CMS 即時編輯。localStorage 沒有跨裝置同步或可靠備份，對作品集 Demo 可接受，但 UI 必須如實告知。
- 沒有後端、資料庫、登入、金流、訂房或第三方訂房 API。住宿外部連結不等於本站交易。

## 驗收條件

1. 內容：四份 JSON 連結完整、主要卡片有來源與更新資訊、沒有未授權媒體或把 AI 圖冒充實景。
2. UI：1440／390px 遵守首頁規格；320／768px 不溢出；實際圖片裁切保留主體。
3. 流程：搜尋、區域導覽、收藏、行程保存、外站連結、空態／錯誤狀態可操作。
4. 無障礙：鍵盤、焦點、Drawer、表單標籤、圖片 alt、對比、reduced motion 及 200% 縮放核查。
5. 工程：執行專案實際 build／type check；必要的互動以瀏覽器檢查。未測項明列，不以設計稿推定可用。

## 需要人工確認的決策

1. 品牌字標向量稿、商標可用性與最終中文字級／英文字型比例。
2. 首頁 Hero 與住宿素材來源、授權／預算；這是實作高品質影像首頁的主要依賴。
3. 首批要收錄的城市、景點、住宿與故事名單，以及誰負責內容正確性與更新。
4. 中文為主、英文輔助是否符合預期；完整雙語需另排內容與實作量。
5. 行程只存本機是否符合 Demo 目標；若需跨裝置，必須另立後續階段與資料服務方案。
