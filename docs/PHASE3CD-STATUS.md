# Phase 3C–3D：行程進階管理與資料安全

本文件補充 [Phase 3B](PHASE3B-STATUS.md)；Phase 0 設計文件及 `isle-and-wander:trips:v1` localStorage Key 保持原狀。

## 行程操作

- 每筆景點可指定另一個 Day 移動。Store 先檢查目標是否重複，再以單次資料更新同時從原日移除、加入目標日；失敗時原安排保留。
- 複製整段行程會建立新 UUID、加「副本」名稱並深複製每日景點 ID 陣列。原行程不受副本修改影響。
- 複製單日安排先顯示目標日期現有景點及待新增景點。目標已有安排時，確認後才將不重複的景點追加，保留原有順序。
- Planner 列表與編輯頁顯示旅行天數、安排景點數、有安排的日期數及最後修改日期。未推算交通、費用或停留時間。

## JSON 備份格式

匯出單一 UTF-8 JSON 檔；不包含完整景點資料、圖片、收藏或憑證。

```json
{
  "app": "isle-and-wander",
  "schemaVersion": 1,
  "exportedAt": "2026-10-30T00:00:00.000Z",
  "trips": [{
    "id": "trip-<uuid>",
    "title": "東海岸慢行",
    "createdAt": "2026-10-30T00:00:00.000Z",
    "updatedAt": "2026-10-30T00:00:00.000Z",
    "days": [{ "dayNumber": 1, "attractionIds": ["attraction-gaomei-wetlands"] }]
  }]
}
```

匯入僅接受本站 v1 備份。上限為 2 MB、100 筆行程；建立、複製與合併後的總筆數也不超過 100。逐筆檢查 ID、非空名稱、ISO 時間、連續的 1–7 天、現有景點 ID 與同一天重複項。無效行程及原因顯示於預覽，不會靜默寫入。備份中的文字只以 Vue 文字節點呈現。

**合併：**現有行程保留；相同 ID 的匯入行程取得新 UUID。再次匯入同一檔案會增加副本，預覽會顯示 ID 衝突數。**取代全部：**含無效行程的備份不可取代；有效備份需再次確認，才會一次取代現有行程。空備份不執行匯入。

瀏覽器禁止 localStorage 寫入時，畫面會說明新資料只在當前工作階段有效，不宣稱永久復原。若儲存限制解除，可在 Planner 點「重新嘗試儲存」。跨分頁使用 `storage` 事件同步，不將收到的事件回寫。建議在取代前先匯出目前行程；清除瀏覽資料後可從已下載的備份重新匯入。本站沒有雲端備份。

## UI 修正

- 手機行程景點的資訊、排序工具列與跨日移動分區；排序按鈕保留至少約 44px 觸控範圍，Disabled 狀態仍可辨識。
- 空白日期縮減留白，保留 Day、景點數及加入入口。
- Explore 縣市 Popover 與觸發欄位同寬、右緣對齊，避免蓋住搜尋操作。「全部縣市」移至縣市選項之後並降低視覺權重。Trigger 鍵盤焦點以單一加粗邊框呈現。
- Explore 卡片在加入行程按鈕成為連結的同層元素後，移除詳情連結的 `height:100%`，避免首張卡的連結攔截下一張卡片或加入按鈕的點擊。
- 加入行程面板保留原生 Select，改善手機間距、名稱換行及焦點邊框。
