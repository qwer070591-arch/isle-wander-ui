# User Flows

每條流程以「入口 → 主要操作 → 成功狀態 → 例外」描述；Phase 1 實作優先順序見 [IMPLEMENTATION-ROADMAP.md](IMPLEMENTATION-ROADMAP.md)。

| 流程 | 入口與步驟 | 成功狀態 | 例外／恢復 |
|---|---|---|---|
| 從區域探索 | 首頁 `Discover by Region` → 區域入口 → `/destinations/?region=east` → 城市 → 相關景點 | 看見區域脈絡與可選的城市、景點 | 零資料顯示區域說明與返回全部；無效 query 回全部並提示 |
| 搜尋景點 | Header 搜尋 → 輸入關鍵字 → 結果清單 → 篩選類型／城市 → 詳情 | URL 保留查詢，結果數與篩選一致 | 零結果可清除條件；載入失敗可重試 |
| 收藏後重訪 | 任一卡片／詳情收藏 → 本機儲存 → `/favorites/` → 開啟詳情 | 收藏按鈕狀態同步，刷新後仍在 | localStorage 不可用時即時提示，不假裝已存；資料項目被移除時跳過並提示 |
| 建立行程 | `/planner/` 建立名稱與日期範圍 → 加入景點 → 分配日期 → 調整順序 → 自動本機保存 | 重新整理可恢復，日程清楚顯示 | 日期錯誤不能儲存；容量不足提示匯出／簡化（匯出為後續候選）；離線／無資料仍可看已存名稱 |
| 從故事導向探索 | 首頁故事／`/stories/` → 文章 → 相關城市或景點 → 收藏／加入行程 | 內容與地點脈絡相連 | 相關項目缺失時隱藏該連結並保留文章 |
| 看住宿資訊 | `/stays/` → 城市／特色篩選 → 住宿詳情 → 明示外站的官網連結 | 清楚知道本站只提供編輯介紹 | 官網缺失則不顯示外站 CTA；過期內容標示更新日期 |

## 跨流程規則

1. 不在未確認的資訊上製造交易預期：無「預訂」「查看空房」按鈕。
2. 未登入是正常狀態；收藏與行程的持久性只限該瀏覽器與來源網域。使用隱私模式或清除資料可能失去內容。
3. 搜尋／篩選更新 URL query；收藏／行程更新 Pinia 並同步 localStorage。瀏覽器返回應還原清單狀態與捲動位置（可行時）。
4. 螢幕閱讀器需聽到搜尋結果數、收藏狀態及行程儲存失敗；不對每次成功自動儲存持續播報，避免噪音。
5. 首次進站不強制 onboarding。空收藏與空行程提供「探索景點」等明確下一步。

## 核心任務驗收

- 390px 下從首頁搜尋入口到景點結果、詳情、收藏，無水平溢出且全程鍵盤可操作。
- 從區域入口到城市與景點，路由與 query 可分享；刷新後篩選仍在。
- 建立兩日行程、加入與重排項目，刷新後內容一致；儲存不可用時明確報錯。
